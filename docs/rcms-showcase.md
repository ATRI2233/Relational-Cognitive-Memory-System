# RCMS — 关系认知记忆系统 技术展示

RCMS（Relational Cognitive Memory System）是 AI Agent 的关系认知记忆引擎。在严格 Token 成本约束下，让 AI 在长期对话中拥有人际关系感知——记住人、理解关系、感知氛围、积累共同语境。

---

## 模块一：状态关系 — 关系弧 + 情绪 + 会话

### 解决的问题

AI 对每个人应该有不同的"熟悉度"和"氛围感"——对老友更随意，对新用户更礼貌；气氛好时更亲近，气氛僵时更谨慎。

### 关系弧：五阶段递进

```
stranger ──→ familiar ──→ rapport ──→ history
    ↑                        |
    └── drift ←── reconnect ──┘
```

晋升阈值递增：4 → 10 → 20 → 35，越往上越难，模拟真实人际关系。

**两种更新途径：**
- 日常对话：每次 `_post_update` 微调 +0.02
- LLM 分析：`relationship_delta ∈ {-1, 0, +1}`，每次 ±0.5

### 情绪追踪：暖度 + 张力

| 情绪 | 暖度 | 张力 |
|------|------|------|
| 温暖 | +0.5 | 0.0 |
| 兴奋 | +0.6 | 0.3 |
| 低落 | -0.3 | 0.1 |
| 焦虑 | -0.4 | 0.7 |
| 防御 | -0.2 | 0.6 |
| 疏远 | -0.5 | 0.4 |
| 平静 | +0.1 | 0.0 |

**残留衰减**：每次新对话 warmth / tension × 0.6，保证情绪不会永不消退。

### 悬案追踪：三层生命周期

```
话题被提出
  → 超过 5 轮未提：展示前缀 "↘"（可能已冷）
  → 超过 10 轮未提：不展示（太久了）
  → 超过 15 轮未提：自动归档到认知蒸馏
  → 蒸馏触发：同时归档当前悬案
```

解决经典 AI 问题："每次都问同一个未完成话题"。

## 模块二：用户画像 — identity_memory

### 解决的问题

不只是记住"小明说过什么"，而是构建用户画像：他是什么样的人、喜欢什么、讨厌什么、说话什么风格、不能提什么。

### 存储结构

```
identity_memory (每人一条)
├── traits[]              特质列表（带强度 + 确认次数）
│   例: {"t":"理性派", "s":5, "c":3}
│       {"t":"不善社交", "s":2, "c":1}
├── preferences{}         喜好/厌恶
│   例: {"likes":["猫","咖啡"], "dislikes":["说教","吵闹"]}
├── communication_style   沟通风格（字符串）
│   例: "说话带喵，喜欢用表情包"
├── self_identity[]       自我认同
│   例: ["理性派", "INFJ", "夜猫子"]
├── core_identity{}       核心身份
│   例: {"职业":"程序员", "角色":"全栈", "标签":"猫奴"}
└── boundaries[]          雷区
    例: ["别说教", "别拿抑郁症开玩笑"]
```

### 核心算法：特质强度衰减

```
每次 LLM 分析时：
  被确认的特质 → 强度重置为 5，确认次数 +1
  未确认的特质 → 强度 -1，但不低于 min(确认次数, 3)
  强度归零     → 自动删除
```

偶然出现的特质快速消退，反复确认的特质稳定沉淀。

### 覆盖写策略

preferences、communication_style、self_identity、core_identity **全量覆盖而非增量合并**。LLM 已参考全部历史，产出即综合快照，增量合并反而引入新旧矛盾。

## 模块三：共同语境 — shared_context + entity_relations

### 解决的问题

长期对话中会形成只有两人懂的梗、反复出现的人和事、必须记住的上下文。这些既不属于"关系状态"也不属于"用户画像"，是独立的积累层。

### 构成

**梗与暗号（shared_context）**

```
例: [梗] 奶茶 → 上次打赌输了请客的那杯
     [梗] 三号线 → 她每天通勤的恶梦
     [边界] 别问家里的事
```

- 来自 LLM 分析的 `shared_jokes` 和 `boundary_hits`
- 按提及频次（omission_count）排序，高频优先展示

**实体关系（entity_relations）**

```
例: 张医生 → 咨询师 → 正在接受其心理咨询
     小明  → 同事   → 在字节跳动做后端
```

- 8b 同步写入图谱边（`memory_graph_edges.relation`）
- 在 `narrative_context` 中展示为"他提过的人/事: 张医生(咨询师·正在接受其心理咨询)"

## 模块四：召回三路记忆 — 三通道融合

### 解决的问题

用户问"他上次说换工作那事后来怎样了？"——从海量历史记忆中找到"小明三周前提到要从字节跳槽"这条相关信息。

### 架构

```
                   用户输入
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌────────────┐ ┌────────────┐ ┌────────────┐
│ 时间重要性  │ │  多维共振   │ │  图谱骨架   │
│            │ │            │ │            │
│ importance │ │ 图扩散扩词  │ │ 关键词查节点│
│ ×          │ │ → embedding│ │ → BFS 取边 │
│ 指数衰减    │ │ → 余弦相似  │ │ → 语义边优先│
│            │ │ → 情绪共振  │ │            │
│ 零 API 成本 │ │ → 重要性兜底│ │ 结构化事实  │
└──────┬─────┘ └──────┬─────┘ └──────┬─────┘
       └──────────────┼──────────────┘
                      ▼
             ┌────────────────┐
             │  融合器         │
             │  保底 → 去重 → │
             │  排序 → 截断   │
             │  (默认 ≤ 5 条) │
             └────────────────┘
```

### 通道 1：时间重要性锚点

```
score = importance × exp(-ln2 × 距今天数 / 半衰期)
```

半衰期默认 30 天。纯本地计算，零 API 成本。

### 通道 2：多维共振

```
基础分 = cos_sim × 0.6 + imp_decay × 0.4
情绪匹配时 × (1 + resonance_bonus)
```

链路：时间词硬过滤 → 图扩散扩词（BFS depth=2）→ embedding 余弦 → 情绪共振加成 → 关键词 SQL 兜底 → 重要性兜底。

### 通道 3：图谱骨架

```
输出格式: 「A」--[关系]--> 「B」
排序: 带 relation 的语义边优先，纯共现边靠后
```

### 融合器

两阶段：每通道保底取 1 条 → 剩余名额全局按分排序，前 25 字符去重，总召回 ≤ 5 条。

### 防噪音

- 图扩散：纯共现边 BFS 时权重 ×0.1，depth=2
- 向量维度校验：首条维度为标准，不一致则跳过
- 无向边去重：按 `(min(A), max(B))` 写入

## 完整流程

```
输入
  → [状态关系] 加载关系弧 + 情绪残留 + 悬案
  → [用户画像] 加载特质/喜好/风格/认同/雷区
  → [共同语境] 加载梗 + 实体
  → [召回] 三通道融合 → 5 条相关记忆
  → 拼入 system_prompt → LLM 生成回复
  → 保存对话
  → 关系微调 + 情绪衰减 + 悬案检查
  → 可选: LLM 事后分析（特质/喜好/雷区/实体/情绪/关系等 9 项一次完成）
```

## LLM 事后分析：一次调用覆盖全部

```
输入: {用户输入 + AI 回复 + 已知画像}
输出: JSON → 分发到 9 个位置
```

```json
{
  "mood": "温暖", "mood_intensity": 0.8,
  "topic_shift": true, "key_points": [...],
  "relationship_delta": 1,
  "traits_updates": [...], "speech_quirks": [...],
  "preferences": {...}, "communication_style": "...",
  "self_identity": [...], "core_identity": {...},
  "boundary_hits": [...], "dangling_threads": [...],
  "importance": 0.8, "entities": [...]
}
```

| 字段 | 写入目标 |
|------|----------|
| mood + mood_intensity | emotional_trace |
| topic_shift + key_points | session_state.focus_topic |
| relationship_delta | relationship_arc |
| traits_updates + speech_quirks | identity_memory.traits（强度更新） |
| preferences / communication_style / self_identity / core_identity | identity_memory（覆盖写） |
| shared_jokes | shared_context |
| boundary_hits | identity_memory.boundaries（集合合并） |
| dangling_threads | cognitive_distill + session_state |
| entities | 图谱边（memory_graph_edges.relation）|
| importance ≥ 0.5 | cognitive_distill（事件存档） |

## 防退化机制一览

| 问题 | 方案 |
|------|------|
| 偶然提一次特质就永久记住 | 强度衰减，未确认每次 -1 |
| 每次都问同一个未完成话题 | 悬案三层生命周期，超 15 轮归档 |
| 图扩散跑到无关节点 | 纯共现边 ×0.1，depth=2 |
| 高频/低频对话漏蒸馏 | 轮数/时间双条件触发（30轮/60分钟） |
| 情绪永不消退 | 每次 ×0.6 衰减 |
| 图边 A→B B→A 双条 | 排序去重写入 |
| 空 relation 覆盖有值 | CASE WHEN 保护 |
| embedding 模型切换维度不对 | 首条维度校验，不一致跳过 |
| 用户不存在操作失败 | INSERT OR IGNORE 惰性初始化 |

## 数据存储结构

```
记忆池
  cognitive_distill ─── 统一记忆表（原始事件 + 蒸馏摘要混合存储）
  chat_history      ─── 原始对话全量存档

当前状态（不可揉入蒸馏表，必须独立）
  identity_memory   ─── 模块二：用户画像
  relationship_arc  ─── 模块一：关系弧
  emotional_trace   ─── 模块一：情绪追踪
  session_state     ─── 模块一：会话状态（悬案/焦点/残留情绪）

积累语境
  shared_context    ─── 模块三：梗 + 共同语境
  entity_relations  ─── 模块三：实体关系事实

图谱
  memory_graph_nodes ─── 关键词节点
  memory_graph_edges ─── 共现边 + 语义关系边
```

## 架构亮点

**Mixin 架构**：7 个 Mixin 各 100-200 行，职责单一

**回调热插拔**：`RCMS(db_path, llm_call=my_llm)`，插件走回调，独立用内置 fallback

**向量本地缓存**：Embedding 存 SQLite BLOB，NumPy 矩阵运算，不重复调 API

**配置驱动**：所有阈值 `config.json` 可配，代码常量仅为默认值

**展示压缩**：traits 按强度排序展示 top5 + "及其他"，时间模糊为"前两天/不久前/前段时间/很久以前"

**成本控制**：默认不调 LLM 分析 · 单次覆盖 9 模块 · 总召回 ≤ 5 条 · 采样跳过 · 向量缓存
